\chapter{Proposta de Solução}

Este capítulo apresenta a proposta de solução para o problema investigado, descrevendo a documentação técnica inicial do sistema, os requisitos identificados, os principais artefatos de modelagem e a visão geral do protótipo.

\section{Documentação Técnica}

A documentação técnica da solução tem como objetivo organizar, de forma estruturada, as decisões relacionadas ao funcionamento do sistema, às integrações previstas e ao comportamento esperado da aplicação. Nesta etapa, a documentação cumpre o papel de consolidar os resultados da pesquisa com usuários e transformá-los em especificações iniciais para desenvolvimento.

\subsection{Levantamento de Requisitos}

O levantamento de requisitos foi orientado pelos achados da pesquisa qualitativa e pelas histórias de usuário definidas no capítulo anterior. A seguir, são apresentados requisitos iniciais que servirão de base para o detalhamento técnico da solução.

\subsubsection{Requisitos Funcionais}

\begin{itemize}
    \item O sistema deve permitir o registro de entradas e saídas financeiras por meio de mensagens em linguagem natural no WhatsApp.
    \item O sistema deve classificar automaticamente os lançamentos em categorias financeiras.
    \item O sistema deve confirmar ao usuário os registros realizados e permitir correção em caso de interpretação inadequada.
    \item O sistema deve gerar relatórios periódicos com síntese de gastos, entradas e saldo.
    \item O sistema deve identificar gastos recorrentes e emitir alertas sobre assinaturas ou débitos automáticos.
    \item O sistema deve permitir o cadastro e acompanhamento de metas financeiras.
    \item O sistema deve disponibilizar uma interface web para consulta de gráficos e informações consolidadas.
\end{itemize}

\subsubsection{Requisitos Não Funcionais}

\begin{itemize}
    \item A solução deve apresentar fluxo de uso simples e compatível com usuários sem conhecimento técnico.
    \item O tempo de resposta das interações conversacionais deve ser adequado ao contexto de mensagens instantâneas.
    \item O sistema deve garantir persistência e integridade dos dados financeiros registrados.
    \item A arquitetura deve permitir evolução modular das integrações e serviços.
    \item A aplicação deve ser passível de execução em ambiente conteinerizado para facilitar implantação e manutenção.
\end{itemize}

\subsection{Modelagem}

Os artefatos de modelagem têm como finalidade representar o comportamento, a estrutura e os dados da solução de forma compreensível para análise e implementação.

\subsubsection{Diagrama de Casos de Uso}

O diagrama de casos de uso consiste em uma representação da UML utilizada para apresentar, de maneira visual, as principais funcionalidades oferecidas por um sistema e as interações estabelecidas entre essas funcionalidades e seus atores. Os atores correspondem a usuários, sistemas externos ou outras entidades que se relacionam com o sistema, enquanto os casos de uso representam ações, processos ou objetivos que podem ser executados. Esse tipo de diagrama assume papel relevante nas etapas de levantamento e modelagem de requisitos, uma vez que contribui para a delimitação do escopo do sistema, para a identificação de suas funcionalidades centrais e para a facilitação da comunicação entre desenvolvedores, orientadores e demais envolvidos no projeto.

No diagrama de casos de uso desenvolvido para a proposta deste trabalho, o ator principal é o Usuário, responsável por interagir com o sistema para registrar transações financeiras por meio do WhatsApp, consultar saldo, acessar relatórios financeiros, cadastrar e acompanhar metas, visualizar o dashboard web e receber alertas financeiros. O diagrama também contempla funcionalidades internas necessárias ao funcionamento da solução, tais como interpretar linguagem natural, classificar transações, confirmar registros financeiros, identificar gastos recorrentes, gerar recomendações personalizadas, emitir relatórios e armazenar dados financeiros.

\subsubsection{Diagrama de Classes}

O diagrama de classes é um dos diagramas mais utilizados da UML (Unified Modeling Language), sendo responsável por representar a estrutura estática de um sistema orientado a objetos. Esse tipo de diagrama permite demonstrar as classes existentes no sistema, seus atributos, métodos e os relacionamentos entre elas. Além disso, o diagrama de classes auxilia na visualização da organização do software, contribuindo para a compreensão da arquitetura do sistema e das responsabilidades de cada componente.

No contexto da presente proposta, o diagrama de classes representa os principais elementos relacionados ao funcionamento do sistema de gerenciamento financeiro integrado ao WhatsApp. A estrutura contempla classes responsáveis pelo gerenciamento de usuários, mensagens, transações financeiras, categorias, metas financeiras e notificações. Além disso, o diagrama também apresenta uma classe de serviço responsável pelas funcionalidades de inteligência artificial, incluindo processamento de mensagens, geração de recomendações e emissão de alertas financeiros. Os relacionamentos apresentados demonstram como os componentes do sistema se conectam, permitindo a integração entre o controle financeiro, a comunicação conversacional e os recursos inteligentes propostos pela aplicação.

\subsection{Protótipo da Interface de Usuário}

O protótipo da solução deverá contemplar dois eixos principais: a experiência conversacional no WhatsApp e a interface web para visualização de relatórios. Na interação conversacional, espera-se um fluxo enxuto para registrar transações, revisar classificações e receber alertas. Na interface web, a proposta inclui visualização de categorias, evolução de gastos, saldo e metas financeiras.

Nesta versão do documento, o protótipo permanece descrito em nível conceitual, servindo como guia para a etapa de refinamento visual e técnico. A inclusão das telas finais e dos fluxos completos deverá ser realizada em etapa posterior do trabalho.
